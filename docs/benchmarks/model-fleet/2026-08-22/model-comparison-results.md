# Luna and Terra read-only benchmark results, 2026-08-22

## Scope

This record closes the model-analysis portions of ROADMAP #132 and #135.

- Terra effort sweep: `low`, `medium`, `high`, `xhigh`, and `max`.
- Terra `ultra` was intentionally excluded on cost.
- Advanced-context comparison: Luna `xhigh`, Terra `medium`, and Terra
  `xhigh` on the same four frozen escalated/deferred cases.
- Every model arm was read-only. The Zen fleet exclusively owned claims, source
  changes, builds, verification, and the BuildLock.
- No model candidate from these analyses was applied. Raw responses are retained
  beside this file for later reconciliation.

The full-sweep prompt is `terra-effort-input.md`. The advanced prompt is
`advanced-context-input.md`.

| xhigh | fail, prohibited result paths exposed | pass | fail switch, pass store order | pass | bounded declaration and candidate reconciliation |
| max | fail, prohibited #132 outcome exposed | pass | fail switch, pass store order | pass | complete but uncompiled BO6 candidate |

The hidden GCC answer was deliberately the same compiler-quirk gate used for
Luna. The target's 51-entry table needs only empty boundary cases `0` and
`50` around live cases `10`, `11`, `20`, and `40`. Every Terra effort
instead recommended labeling all interior values. Every effort did correctly
put the Boolean true store before the related zero store.

This is the decisive result. Terra does not qualify for autonomous fleet work at
any tested effort. Increasing effort did not solve the known GCC 2.7.2 failure,
and three of five settings lost benchmark evidence isolation. Max produced no
capability that justifies its higher cost.

Terra remains useful only behind a root gate. Low and high followed the project
process on the live Stage A case. High made the best use of durable repository
history by recovering the preserved one-instruction-short seed instead of
redesigning it. No full-sweep arm supplied match proof, and none was authorized
to try.

Comparable token or dollar usage was not exposed. Wall-time comparison is not
valid because arms were staggered around concurrency limits and two user
interruptions. Raw response sizes are preserved, but output bytes are not a
cost substitute.

All three correctly refused to treat isolated score zero as full-overlay proof,
correctly avoided rerunning exhausted permutation, and kept compiler-rejected C
out of the near pool.

Terra xhigh is the best advanced-context analysis setting on this sample. It
added a material control-flow diagnosis that Terra medium missed, while Luna
xhigh produced the most aggressive candidate draft. Neither role is autonomous:
all returned work remains an uncompiled reconciliation input.

## Decision

- Zen remains the production fleet backend and sole owner of stateful work.
- Luna xhigh remains approved for bounded root-gated candidate drafting.
- Terra xhigh is approved for bounded root-gated analysis of already advanced
  escalated/deferred work when the extra diagnostic depth is worth its cost.
- Terra low is acceptable for cheaper read-only evidence collection, but not for
  compiler conclusions.
- Terra medium, high, xhigh, and max do not become autonomous workers.
- Terra max is not an economical default.
- Terra ultra is out of scope by owner decision.

No candidates are discarded. Reconciliation should start with the exact raw
responses and existing immutable candidate generations, one case at a time,
after the Zen fleet is stopped and the root owns the BuildLock.
